# SEER APP (Explorer) v2 — product brief (folder apps/explorer-v2: static index.html + app.js + app.css + icons.js + data/ + assets/; the driver copies it to public/p/explorer-v2)
Read first: app.js (the whole render/state logic), app.css, index.html, data/*.json, and the notes in apps/explorer/public/previews/h/*.md (PRODUCT.md, DESIGN_SYSTEM.md, REDESIGN_NOTES.md, FINAL_QA.md, INTEGRATION_QA.md). Today it is a conventional prediction-market page: a featured carousel, a filter strip, a grid of tiles and a right detail panel. The owner says it reads as a copy of a default prediction market, with no innovation. v2 must be re-architected as "the Etherscan of Seer": a place where you FIND, UNDERSTAND and TRADE across ALL market types, and where every market answers WHO ASKED / WHAT IS PRICED / HOW TO USE THE SIGNAL. You may split app.js into ES modules (<script type="module">), restructure the DOM freely and rewrite CSS completely, but every capability must survive.
## New information architecture
1. Second bar (keep functions, restyle): Markets | Leaderboard | Policies menu, search (/ to focus: market, id, asker, outcome), Human | Agent switch, Create Market, and whatever else exists today.
2. COMMAND-FIRST HEADER: instead of a hero carousel, a wide command bar ("Search a question, market id, asker or outcome") with scope chips for market types (All, Binary, Categorical, Scalar, Multi-outcome, Futarchy, Deep, Opportunity, Risk where data allows), and under it ONE quiet line: "<n> markets, snapshot Oct 18 · demo orders" (no metric cards). The old featured/trending carousel becomes a slim "Movers" rail (horizontal, 6-8 items: image, question, chance with change arrow; keyboard navigable; auto-advance paused on hover; same data/links) placed beneath the command bar.
3. MAIN = TWO PANES. LEFT (about 62%): the INDEX, an Etherscan-style dense table with a sticky header: Market (avatar + title + verified tick), Asked by (name or short address + profile link), Prices (a plain-words phrase of what the market prices), Chance (leading outcome with a 4px animated bar), Volume, Liquidity, Resolves, Chain, Type; sortable columns; zebra-free, 52px rows, row hover reveals a Quick buy affordance; selected row has a violet inset marker; arrow-key navigation; infinite/paged exactly as today. All existing filters (Topic, State, Verified, Chain, Type, More, Volume sort asc/desc) live in a single sticky filter row with removable applied-filter tags. RIGHT (about 38%): the INSPECTOR, sticky: "Asked by / Priced / How to read" strip first, then outcomes as animated bars with exact %, a new interactive price-history chart (see below), the trade ticket (Buy/Sell, amount, estimated receive, 'Preview buy' demo flow with honest mock signing), resolver/oracle block (Reality.eth, Kleros, contract, chain, created, verified), liquidity/pools, activity feed, and share / CSV export / star / open full page — everything the current detail has.
4. VIEW SWITCH (segmented control with sliding thumb, keeps today's three views Tiles | Index | Activity and adds one): INDEX (default, above), TILES (redesigned cards: question, leading outcomes with exact %, a real microchart from market-chart data, buy buttons, same quick-buy popover behaviour), ACTIVITY (redesigned timeline feed grouped by hour with type icons), MAP (NEW: a treemap of all filtered markets sized by volume and coloured by the leading chance; hover = tooltip, click = select into inspector; animates on filter change; falls back to a list for screen readers).
5. Full market page (route/hash as today) uses the same inspector content in a roomy two-column layout with tabs (Overview, Trades/Activity, Resolution, Related) so nothing is lost. Leaderboard and Policies pages restyled with the same language (podium for top 3 traders).
## The chart language
Price history = smooth monotone area chart with gradient fill under the leading outcome, other outcomes as thin lines, range pills with sliding thumb (1D 1W 1M All), animated draw-in, crosshair + glass tooltip, direct labels at line ends, keyboard-reachable. Chance bars and microcharts reuse one small shared chart helper so all charts look related. Use the real data in data/market-chart.json and data/markets-charts.json.
