# Competitor patterns to borrow and beat

Observations below come only from the four named local fact files. “Seer decision” means a proposed design, not verified functionality. These captures establish content and capabilities, not measured usability or current availability.

| Surface / pattern | Evidence | Seer decision: borrow → improve |
| --- | --- | --- |
| Explorer: scoped search | Etherscan search lists addresses, tokens, name tags, domains, labels, and websites. [Source](https://etherscan.io) | Make search prominent → show supported Seer entity types explicitly, group results by type, and keep the query editable in the empty state. Verify search capabilities before exposing scopes. |
| Explorer: saved investigations | Etherscan offers saved filters/presets and customizable latest-block/transaction cards. [Source](https://etherscan.io) | Offer compact presets → persist active filters in the URL and show removable filter chips plus Reset. Start with useful defaults rather than requiring customization. |
| Explorer: freshness and finality | Etherscan labels a five-minute transaction update cadence and exposes safe/finalized block heights. [Source](https://etherscan.io) | Put freshness beside metrics → distinguish observed time, refresh status, and settlement status; stale data must not look live. |
| Explorer: public browsing | Manifold exposes Browse and a skip-to-main-content link; its signup pitch offers a starting balance. [Source](https://manifold.markets) | Preserve a clear browsing entrance and keyboard skip link → explain Seer’s actual wallet/funding prerequisites at the action boundary. Do not copy an unsupported starting-balance offer. |
| Futarchy: proposal lifecycle | MetaDAO documentation separates creating, trading, and finalizing proposals. [Source](https://docs.metadao.fi) | Mirror those stages in proposal detail → keep current stage, next permitted action, and explanatory help together. Documentation headings alone do not verify MetaDAO’s screen layout. |
| Futarchy: explicit decision basis | The futarchy reference describes conditional assets tied to policy adoption and flags thin liquidity, manipulation, and metric-definition challenges. [Source](https://en.wikipedia.org/wiki/Futarchy) | Compare adoption/non-adoption scenarios with identical units and time windows → place the decision metric, liquidity context, and caveats beside the comparison. Do not imply that Seer automatically executes a policy. |
| Opportunity Markets: interpretable prices | The reference explains market-implied probability and Yes/No contracts. [Source](https://en.wikipedia.org/wiki/Prediction_market) | Pair price with implied probability where the contract supports that interpretation → label payout basis and fees; never call implied probability a guaranteed outcome or return. |
| Opportunity Markets: resolution clarity | The reference describes Kalshi source agencies/payout criteria and Polymarket’s optimistic-oracle dispute window. These are secondary-source descriptions. [Source](https://en.wikipedia.org/wiki/Prediction_market) | Put source, criterion, deadline, and dispute path near the action → expose the exact Seer market’s terms, not a copied competitor oracle model. |
| Risk Pricing: decision-ready dimensions | LlamaRisk describes exposure, liquidations, oracle performance, scenario modeling, and stress testing. [Source](https://www.llamarisk.com) | Group risk by exposure, liquidity, and oracle dependencies → attach units, scenario assumptions, and source timestamps to every proposed metric. |
| Risk Pricing: separate observation from intervention | LlamaGuard names Valuation, Verification, and Enforcement layers; Gauntlet describes quantitative frameworks with human oversight. [LlamaRisk](https://www.llamarisk.com), [Gauntlet](https://gauntlet.xyz) | Separate measured inputs, model estimates, and proposed responses → state who can act and what remains a recommendation. Never imply automatic Seer enforcement without evidence. |

## Evidence limits that affect direction

- `explorer_patterns.json` supports Etherscan/Manifold patterns, not Seer Explorer requirements.
- `futarchy.json` mixes general theory with MetaDAO/Gnosis material; theory is not a shipped Seer workflow.
- `opportunity_markets.json` is general prediction-market background from Wikipedia, not a dedicated opportunity-product audit. It does not verify a ranking formula, yield strategy, or arbitrage detector.
- `risk_pricing.json` includes Chaos Labs AI-workflow messaging as well as DeFi-risk providers. Do not treat the captured Chaos Labs homepage as evidence of a specific DeFi dashboard layout.
